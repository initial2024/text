# OGRELAY13: batched resource hardening

Three changes in independent OmniGate candidate branch only. (1) Per-response outgoing WebSocket pacing at 2 MiB high and 512 KiB low watermark, observing OkHttp queueSize, waiting up to 30 seconds in worker, then failing closed without resEnd or replay. Previously accepted chunks are left intact; upstream native response is drained to natural EOF without auto retry or model Stop. (2) Public Relay request admission limited to 6 concurrent local native HTTP requests via semaphore; over-cap requests get resError 503 with no model submission, permit released even on exceptions or stale generations. (3) Local upstream failure errors and public health exceptions no longer reflect arbitrary Java exception messages that could include sensitive URLs or headers.

Tests: pure Java pressure hysteresis, stall, stale epoch, six slots and release; static source binding; exact-HEAD Android library/DEX/signing identity preflight and OGRELAY03/07/12 regressions. QueueSize means local OkHttp queue admission only, not remote client receipt. Slow network can fail after 30 s; candidate requires real Android controlled throttling, model/SSE/DSH UI verification before signed release. Existing installed APK, Relay keys, owner 409, 8787/1604 and original app unchanged. No GPL-3.0 source imported.
## Follow-up same-HEAD hardening
- Restored the original spaced handleRequest(msg, generation, owner) call to satisfy the OGRELAY03 static source guard; exact socket epoch semantics were unchanged. Its first post-OGRELAY13 CI failed a format-only source assertion even though 29 JVM owner tests passed; do not hide that failure.
- RelaySseCompletionGate now also requires at least one non-empty prior SSE data event before a full [DONE] (not just a bare terminal marker or heartbeat); this prevents a trivial false-success. The upstream native Sidecar remains responsible for semantic nonempty content/tool validation. This change does NOT claim UI/model completion verification.
